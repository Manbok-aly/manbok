# 시간복잡도 정리

## 시간복잡도 점근 표기법 학습

### 시간복잡도

시간복잡도란 간단하게
`시간복잡도 = 입력크기 n에 대한 방정식` 이라고 할수있다.

이런 시간복잡도는 보통 최악의 경우로 기본연산 시간을 정리해서 따진다.

```md
### 기본연산시간

기본연산시간이란 일반 산술연산(+,=,/,\*,%) 그리고 비트연산(&,|,^,~,<<,>> 등등)
대입연산자까지 포함하는 경우도 있다고한다.
```

이런 기본 연산시간 n에 대해 알고리즘 동작에 필요한 시간을 n에 대한 수식으로 포현한것이 바로 시간복잡도이다.

`ex-1`

```c
#include <stdio.h>

int main(void)
{
    int n = 5;

    for (int i = 0; i < n; i++)
    {
        printf("%d\n", i);
    }

    return 0;
}

```

임의로 예시를 c로 하나 작성해보았다.
해당 코드에서 보면 0부터 4까지 출력하는 반복문이다.
이런 간단한 연산은 입력값 N에 따른 시간복잡도가 선형적으로 변화한다.

하지만 중첩 반복문을 이용한다면 어떻게 될까

```c
#include <stdio.h>

int main(void) {
    for (int i = 2; i <= 9; i++) {
        for (int j = 1; j <= 9; j++) {
            printf("%d x %d = %d\n", i, j, i * j);
        }
        printf("\n");
    }
    return 0;
}
```

구구단을 출력하는 중첩반복문을 작성해보았다.
해당 알고리즘에서는 T(n) 따라 n^2의 형태의 그래프를 그리고 있다.

앞서 두 예시에 따라 알수있는것, 선형적이면 그래프가 크게 변화하지 않으나
구구단 중첩문과 같은 경우 최고차항에 따라 그래프의 시간`T(n)`이 좌우되기 때문에 n^2에 따라 크게 좌우된다.
다른 차항들은 그래프의 증가에 따라 크게 영향을 끼치지 않기 때문에 최고차항을 제외한 나머지는 크게 보지 않는것입니다.

n^2+3n+1은 점근적으로 n^2에 수렴하기 때문이죠.

여기서 점근적 표기법에는 총 3가지가 있습니다.

1. 빅오 (O)
2. 빅 오메가 (_omega_)
3. 빅 세타 (_theta_)

이중 많이 쓰이는것은 빅 오 표기법입니다.

### 빅오 표기법(Big-O notaiton)

빅오 표기법은 다음과 같습니다

`𝑓(𝑥)= O(g(n))`

이때 g(n)을 함수 𝑓(n)의 점근적 상한(asymptotic upper bound)이라고 합니다.

간단히 이야기해서 𝑓(n)의 복잡도는 g(n)보다 작거나 같다는 의미입니다.

#### `(𝑓(n)≤g(n))`

[그래프 삽입]

= 아무리 빨라도 이정도보다 빠를순 없다.
이라고 간단히 해석할수있을거같습니다

### 빅 오메가 표기법(Big-omega notation)

빅 오메가는 빅오의 반대라고 보면 된다.

`𝑓(n) = Ω(g(n))`

이때 g(n)은 𝑓(n)의 점근적 하한(asymptotic lower bound)이다.
빅오가 위에서 막아주는 천장이라면, 빅 오메가는 아래에서 받쳐주는 바닥 같은 느낌이다.

#### `𝑓(n) ≥ c·g(n)` (n ≥ n₀ 인 모든 n에 대해, c > 0)

[그래프 삽입]

= 아무리 빨라도 이정도보다 빠를순 없다.

예를 들어 𝑓(n) = 3n^2 + 2n 이면
c = 3, n₀ = 1 로 잡았을때 모든 n ≥ 1 에서 3n^2 + 2n ≥ 3n^2 이 성립하니까 `Ω(n^2)` 이다.

하한이라서 `Ω(n)`, `Ω(1)` 이라고 해도 틀린건 아닌데
"최소 1번은 돈다" 같은 말이라 별 의미가 없다. 그래서 보통 제일 딱 맞는 하한을 적는다.

### 빅 세타 표기법(Big-theta notation)

빅 세타는 빅오랑 빅 오메가를 둘다 만족하는 경우다.

`𝑓(n) = Θ(g(n))`

#### `c1·g(n) ≤ 𝑓(n) ≤ c2·g(n)` (n ≥ n₀ 인 모든 n에 대해)

[그래프 삽입]

위아래로 둘다 g(n)에 막혀있으니까 "딱 이만큼 증가한다"는 뜻이다.

앞에서 본 n^2 + 3n + 1 로 확인해보면

```md
아래쪽 : n^2 ≤ n^2 + 3n + 1 → c1 = 1, 모든 n ≥ 1 에서 성립
위쪽 : n^2 + 3n + 1 ≤ 2n^2 → n^2 - 3n - 1 ≥ 0 이어야 함
→ n = 4 부터 성립 (16 - 12 - 1 = 3 ≥ 0)
→ c1 = 1, c2 = 2, n₀ = 4 로 Θ(n^2)
```

세개를 한번에 정리하면

| 표기 | 의미        | 한줄 해석                |
| ---- | ----------- | ------------------------ |
| O    | 상한        | 이것보다 느려지진 않는다 |
| Ω    | 하한        | 이것보다 빨라지진 않는다 |
| Θ    | 상한 = 하한 | 딱 이만큼                |

엄밀하게 따지면 Θ가 제일 정확한데, 코테나 블로그에서는 빅오를 제일 많이 쓴다.
"최악이어도 이거보단 안느리다" 정도만 알면 충분한 경우가 대부분이기 때문이다.

## 복잡도 계산 규칙과 대표 복잡도 학습

### 연산 횟수 세보기

규칙을 쓰기 전에 앞에서 쓴 ex-1 반복문을 연산 하나하나 직접 세보면 이렇다.

`ex-2`

```c
for (int i = 0; i < n; i++)   // i = 0 : 1번
{                             // i < n : n + 1번 (마지막에 거짓 한번 포함)
    printf("%d\n", i);        // printf : n번
}                             // i++ : n번
```

다 더하면

`T(n) = 1 + (n + 1) + n + n = 3n + 2`

여기서 c = 4, n₀ = 2 로 잡으면 n ≥ 2 일때 3n + 2 ≤ 4n 이 성립하니까 `O(n)` 이다.

매번 이렇게 다 세는건 번거롭고, 어차피 상수랑 낮은 차항은 버려지기 때문에
실제로는 아래 규칙으로 바로 계산한다.

### 복잡도 계산 규칙

```md
1. 상수는 버린다 → O(3n) = O(n)
2. 최고차항만 남긴다 → O(n^2 + n) = O(n^2)
3. 순서대로 실행되는 코드는 더한다 (결국 큰쪽만 남음)
4. 중첩된 코드는 곱한다
5. 조건문은 더 오래걸리는 쪽 기준
6. 매번 절반씩 줄어들면 log
```

`ex-3`

```c
#include <stdio.h>

int main(void)
{
    int n = 100;

    for (int i = 0; i < n; i++)        // n번
        printf("%d\n", i);

    for (int i = 0; i < n; i++)        // n * n번
        for (int j = 0; j < n; j++)
            printf("%d %d\n", i, j);

    return 0;
}
```

위에 반복문은 n번, 아래 중첩문은 n^2번 돈다.
합치면 n + n^2 인데 최고차항만 남기면 `O(n^2)` 이다.
앞에 반복문은 전체 복잡도에 영향을 주지 못한다.

`ex-4`

```c
#include <stdio.h>

int main(void)
{
    int n = 1024;
    int cnt = 0;

    for (int i = n; i > 1; i /= 2)
    {
        cnt++;
    }

    printf("%d\n", cnt); // 10

    return 0;
}
```

n이 1024인데 10번밖에 안돈다. 2^10 = 1024 이기 때문이다.
반복 횟수를 k라고 하면 n / 2^k = 1 이 되는 순간 끝나니까 k = log₂n 이다.
이렇게 반씩 잘라나가는 구조가 `O(log n)` 이고, 이분 탐색이 딱 이 모양이다.

### 대표 복잡도

자주 나오는것들을 빠른 순서대로 적으면

- `O(1)` : 배열 인덱스 접근, 누적 합으로 구간 합 구하기
- `O(log N)` : 이분 탐색
- `O(N)` : 배열 한번 쭉 돌기, 투 포인터
- `O(N log N)` : 병합 정렬, 퀵 정렬(평균)
- `O(N^2)` : 이중 반복문, 버블 정렬
- `O(N^3)` : 삼중 반복문, 플로이드-워셜
- `O(2^N)` : 부분집합 전부 보기, 메모이제이션 없는 피보나치
- `O(N!)` : 순열 전부 보기

N에 숫자를 직접 넣어보면 차이가 확실하게 보인다.

| N     | log N  | N log N   | N^2       | 2^N            |
| ----- | ------ | --------- | --------- | -------------- |
| 10    | 약 3.3 | 약 33     | 100       | 1,024          |
| 100   | 약 6.6 | 약 664    | 10,000    | 약 1.3 × 10^30 |
| 1,000 | 약 10  | 약 10,000 | 1,000,000 | ...            |

[그래프 삽입]

N이 100밖에 안되는데 2^N은 10^30이 넘어간다. 사실상 안끝난다고 보면 된다.
